Viva & Demonstration Guide (Table 2)
(a) Vulnerable Implementation

Located in app.py within function sqli_union():

# String formatting concatenates query parameter directly into SQL query_str = f"SELECT id, name, category, price FROM products WHERE name LIKE '%{search_query}%'" cursor.execute(query_str)
(b) Working Exploit Payload

In the search input parameter q:

' UNION SELECT id, username, password, role FROM users --

How it works: The single quote closes the LIKE wildcard. The UNION operator combines the product query with a query against the users table having the exact same 4 columns. The -- comment discards the trailing quote and wildcard.

(c) Root Cause

Unvalidated input concatenation: Direct string injection allows attacker to append arbitrary SQL clauses. Because the database engine cannot distinguish between the developer's original query structure and the attacker's UNION query, it executes both and returns unauthorized table data.

(d) Mitigation Implemented

Parameterized Queries with Wildcard Binding: The SQL query statement is pre-compiled. The search string with wildcards is bound as a single literal parameter.

query_str = "SELECT id, name, category, price FROM products WHERE name LIKE ?" cursor.execute(query_str, (f"%{search_query}%",))
(e) Other Mitigations from Lecture (Theory)
  • Input validation with allow-lists: Validate that search terms only contain alphanumeric characters, discarding SQL tokens like UNION, SELECT, and single quotes.
  • Least-privilege database accounts: Configure the web app's database user to have SELECT permissions strictly on the products table and NO permissions on the users table.
  • Safe errors & column matching prevention: Suppress verbose error messages that reveal table structures and column counts to attackers during discovery.
  • Object-Relational Mapping (ORM): Using established ORMs (e.g. SQLAlchemy) that enforce parameterization natively across all query builders.
