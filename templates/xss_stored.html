Viva & Demonstration Guide (Table 2)
(a) Vulnerable Implementation

Located in Jinja2 template rendering stored comments with | safe filter:

<!-- Raw untrusted user input marked safe, disabling framework auto-escaping --> <div class="comment-content"> {{ item.comment | safe }} </div>
(b) Working Exploit Payload

Submit the following payload into the feedback comment field:

<script>alert('Stored XSS Executed by Anubhav! Cookie: ' + document.cookie)</script>

How it works: The payload is saved to the SQLite database. Whenever any client accesses or refreshes the page, the server embeds the raw script tag into the HTML response. The client's web browser parses and executes the JavaScript in the context of the user's session.

(c) Root Cause

Untrusted user-supplied data rendered without output encoding: The browser cannot distinguish between legitimate application scripts authored by the developer and malicious scripts submitted by an attacker stored in the database.

(d) Mitigation Implemented

Context-Aware Output Encoding & Removal of | safe: All HTML special characters (<, >, &, ", ') are encoded into corresponding safe entities (e.g., &lt;, &gt;). In addition, session cookies are configured with the HttpOnly attribute.

<!-- Jinja2 auto-escapes by default when | safe is omitted --> <div class="comment-content"> {{ item.comment }} </div>
(e) Other Mitigations from Lecture (Theory)
  • Content Security Policy (CSP): HTTP header Content-Security-Policy: default-src 'self'; script-src 'self'; instructs modern browsers to block all inline script execution and unauthorized external script sources.
  • HttpOnly Cookie Flag: Prevents client-side scripts from reading session cookies via document.cookie, blocking session hijacking even if XSS occurs.
  • Sanitizer libraries for rich HTML: When rich text (formatting/markup) is needed, use dedicated sanitizers (e.g., DOMPurify, Bleach) to strip unsafe elements/attributes.
  • Safe DOM Sinks: In frontend JavaScript, utilize safe properties like textContent or innerText instead of dangerous sinks like innerHTML, document.write(), or eval().
